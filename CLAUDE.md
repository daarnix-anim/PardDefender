# PardDefender — инструкция для агента

Прочти этот файл первым. Затем [`PROJECT_MAP.md`](PROJECT_MAP.md) — она генерируется
из кода и всегда актуальна. Для человека есть визуальная карта
[`docs/project-map.html`](docs/project-map.html).

---

## Что это

CEP-расширение для After Effects. Копирует всё, что импортируют в проект, в папку
рядом с проектом, перелинковывает на копию и раскладывает по формату и по
композиции — и на диске, и в панели Project.

Репозиторий: `daarnix-anim/PardDefender`, **приватный**, ветка `main`.
Владелец — один человек, он же единственный пользователь. Интерфейс русский.

---

## Правила, которые нельзя нарушать

Это не стиль, это то, ради чего расширение существует. Нарушение любого из них —
потеря чужой работы.

1. **Оригинал никогда не удаляется, не перемещается и не изменяется.** Только
   копирование. Пользователь чистит «Загрузки» в расчёте на это.
2. **Хост (`.jsx`) не копирует файлы.** ExtendScript не умеет потоковую запись,
   проверку результата и откат. Всё файловое I/O — в Node, на стороне клиента.
   Хост планирует и делает короткую транзакцию relink.
3. **Ничего не удаляется безвозвратно.** Удаление — только в Корзину, через
   `PardHousekeeping.recycle`. Если Корзина недоступна — файл остаётся.
   Никакого «зато удалим насовсем».
4. **Не удалять то, что мы не клали.** Файл удаляется, только если он записан в
   `assets.tsv` как копия, сделанная расширением.
5. **Запись файла — только через `.pdpart` + сверка размера + переименование.**
   Недописанный файл не должен иметь шанса попасть в проект.
6. **План пишется в журнал до первого байта** (`.parddefender/pending.tsv`),
   чтобы следующий старт мог откатить незавершённое.
7. **Никаких токенов внутри расширения.** Токен в установленном у всех
   расширении — это опубликованный токен.
8. **Не двигать элементы, которые разложил пользователь.** Только из корня
   проекта или из папок, созданных самим расширением.

## Команды

```bash
node tests/run-all.js      # 183 проверки, три набора; должно быть зелено
node tools/build-map.js    # пересобрать PROJECT_MAP.md и docs/project-map.html
node tools/build-map.js --check   # проверить, что карта не устарела (CI/хук)
INSTALL_DEV_WINDOWS.bat    # поставить расширение и включить PlayerDebugMode
```

Тесты не требуют After Effects: объектная модель AE замокана в
[`tests/mock-ae.js`](tests/mock-ae.js), настоящие `.jsx` загружаются через `vm`.

**Чего тесты не покрывают:** сами вызовы `item.replace()`,
`replaceWithSequence()`, присвоение `parentFolder`, чтение `usedIn`. Они
проверены против мока, а не против AE. Любую правку в этих местах владелец
проверяет живьём.

## Архитектура за десять строк

```
index.html  →  загружает клиентские модули по порядку
main.js     →  владеет таймерами, решает КОГДА действовать, рисует интерфейс
            →  copy-queue / issues / stats / verify / disk-space /
               housekeeping / updater — по одной ответственности на модуль
            →  evalScript → хост

PardDefenderCore.jsx    JSON для ES3, файлы, пути, классификация форматов
PardDefenderPlan.jsx    рабочая папка, настройки, дерево композиций, ветки
PardDefenderAudit.jsx   один проход → один JSON-отчёт (состояние, не решения)
PardDefenderApply.jsx   relink и раскладка панели — единственные мутации
```

Разделение ответственности жёсткое: **хост сообщает состояние, клиент решает,
когда действовать.** Только клиент знает, сколько элемент лежит в проекте,
перестали ли меняться его байты и сколько раз он уже падал.

Отчёт аудита передаётся через временный файл, а не возвращаемым значением
`evalScript` — на большом проекте он вырастает до сотен килобайт и однажды молча
обрежется.

## Соглашения

**Язык.** Код, имена и комментарии — по-английски. Строки, которые видит
пользователь (интерфейс, тексты ошибок, `@map role`), — по-русски.

**ExtendScript — только ES3.** В `.jsx` нет `JSON`, `Object.keys`,
`Array.indexOf`, `let`/`const`, стрелочных функций, висячих запятых.

**`.jsx` держим в чистом ASCII.** `$.evalFile` не гарантирует кодировку;
кириллица в исходнике хоста ломается молча. Нужен не-ASCII символ — пиши
`\uXXXX`. В клиентских `.js` и `.html` кириллица допустима: там UTF-8.

**Блок `@map` в шапке каждого файла.** Из него строится карта:

```
 * @map role: Одно предложение о том, за что файл отвечает
 * @map status: ready | partial | planned | broken
 * @map note: Чего не хватает (только если status не ready)
```

Добавил файл — добавь блок. Без него файл появится на карте как «не описан»
красной точкой. Связи между файлами **не описываются руками** — генератор
выводит их из кода.

**Не пиши код через shell-heredoc.** Bash в этом окружении съедает обратные
слеши: `\\` превращается в `\`, регулярки тихо ломаются. Проверено дважды.
Используй инструменты записи файлов или отдельный `.py`-скрипт.

**Локальный `jq` выводит `\r\n`.** Любой конвейер `jq | read` требует
`tr -d '\r'`, иначе сравнение строк и `case`-шаблоны молча не совпадают.

## Как карта обновляется сама

Два независимых механизма — карта не должна зависеть от того, кто правил файлы.

**Git-хук** `.githooks/pre-commit` пересобирает карту перед каждым коммитом и
добавляет результат в индекс. Работает для любого редактора и любого агента.
Включается один раз на клон:

```bash
git config core.hooksPath .githooks
```

**Хук Claude Code** в `.claude/settings.json` (`PostToolUse` на `Write|Edit`)
пересобирает карту сразу после правки исходника — чтобы `PROJECT_MAP.md` был
актуален уже внутри сессии, до коммита.

Наблюдатель настроек видит `.claude/` только если она существовала на старте
сессии. Папка создана 29.08.2026 — в сессиях, начатых после этого, хук работает
сразу; в той, где он был создан, он не сработал. Если карта не обновляется
автоматически — проверь `/hooks`, но git-хук закрывает этот случай в любом
случае.

Проверить вручную: `node tools/build-map.js --check` (код возврата 1, если
карта устарела).

## Где лежит состояние

Всё служебное — в `<Рабочая папка>/.parddefender/`:

| Файл | Что внутри |
|---|---|
| `settings.json` | настройки проекта: режимы, интервалы, маршруты, цвета-метки |
| `assets.tsv` | манифест: что, откуда, куда, размер, ветка. **Источник правды о том, что мы клали** |
| `issues.json` | открытые проблемы со счётчиками попыток |
| `stats.json` | накопительные счётчики |
| `pending.tsv` | журнал незавершённой транзакции; существует только во время копирования |

В профиль пользователя пишется ровно один файл —
`%APPDATA%\PardDefender\update.json` (дата проверки обновлений, адрес фида).
Данных проектов там нет.

## Ключевые решения и почему они такие

**Ветка = композиция непосредственно внутри рендерной.** Футаж на третьем уровне
поднимается до неё. Правило намеренно тупое и предсказуемое.

**Рендерная композиция определяется структурно** (`usedIn.length === 0`), плюс
очередь рендера, плюс цвет-метка PIN как ручное переопределение. Никакой
обязательной разметки от пользователя.

**Место на диске окончательное.** Путь вычисляется один раз при копировании и
пишется в манифест. Переименование композиции перестраивает папки в панели AE,
но не двигает файл: перемещение после relink — это новая транзакция с риском, а
рабочие папки лежат на Яндекс.Диске, где любое перемещение означает полную
повторную выгрузку в облако.

**Копирование ждёт композицию.** Таймер отсчитывает не «10 минут с импорта», а
«файл отстоялся И известна его ветка». Тогда путь верен с первого раза и файл
никогда не придётся двигать.

**Ошибки решаются по коду, не по тексту сообщения.** Обновление Node,
переформулировавшее errno, не должно менять поведение повторов.

## Уроки живых прогонов

Каждый стоил реальных данных или времени. Не повторяй.

**Маршрут — это папка.** `01_assets/{branch}/VIDEO` не содержит имени файла. В
1.0.0 его не добавляли, и копии легли файлами `VIDEO`, `VIDEO (2)` без
расширения — AE отказался их перелинковывать. Тест при этом был зелёный, потому
что закреплял ровно то поведение, которое и было багом. **Тест должен проверять
требование, а не то, что код сейчас делает.**

**Никогда не отправляй хосту операцию, которая окажется no-op.** Проход из одних
no-op отчитывается «сделано», запускает следующий аудит и уходит в цикл: 1873
прохода за 13 минут. Клиент обязан сравнить текущее положение (`panelPath`) с
целевым и не строить перемещение вовсе.

**Не перерисовывай список, который не изменился.** `innerHTML` сбрасывает
`scrollTop`, и панель становится непрокручиваемой. У каждого блока есть подпись
содержимого; отсчёты времени округляй до минут, иначе подпись меняется каждую
секунду.

**`explorer.exe` хочет `/select,<путь>` одним аргументом.** Двумя — молча
ничего не делает.

## Как выпускать версию

1. Поднять версию в четырёх местах: `CSXS/manifest.xml` (два вхождения),
   `host/PardDefenderCore.jsx` (`host.version`), `INSTALL_DEV_WINDOWS.bat`,
   `client/index.html`.
2. `node tests/run-all.js` — зелено.
3. `node tools/build-map.js` — карта пересобрана.
4. `git tag vX.Y.Z && git push origin main --tags`
5. `gh release create` — **первая непустая строка описания** попадает в панель
   как единственное предложение о том, что нового.
