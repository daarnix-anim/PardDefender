# Правила работы Gemini / Antigravity в Projector

## Роли

- **Codex — архитектор и ревьюер.** Он исследует продукт, фиксирует архитектуру,
  создаёт ограниченные рабочие задания в `.agents/tasks/` и после выполнения
  независимо проверяет код, тесты и отчёт.
- **Gemini в Antigravity — исполнитель.** Он берёт только указанное владельцем
  задание, реализует его, запускает проверки и сохраняет доказательный отчёт в
  `.agents/reports/`.
- **Владелец — диспетчер.** Он передаёт Gemini номер задания и возвращает Codex
  отчёт или сообщает, что работа завершена. Агенты не переписываются друг с
  другом через сайты или чаты.

## Начало каждой задачи

1. Прочитай этот файл полностью.
2. Прочитай `CLAUDE.md`, релевантные разделы `README.md` и файл задания,
   который явно указал владелец. Не выбирай следующую задачу самостоятельно.
3. Выполни `git status --short` и `node tests/run-all.js` до изменений.
4. Репозиторий может быть грязным. Считай все исходные изменения владельскими:
   не откатывай, не форматируй и не переписывай их без требования задания.
5. Если исходные тесты падают, зафиксируй точный сбой в отчёте. Не маскируй его
   и не утверждай, что он вызван твоей работой без доказательств.

## Исполнение

- Границы задания обязательны. Не реализуй соседние идеи «заодно».
- Сначала найди существующий путь данных и тестовые шаблоны; расширяй их, а не
  создавай параллельную архитектуру.
- Сохраняй ES5-совместимость CEP/ExtendScript там, где она уже требуется.
- Не добавляй зависимости, не меняй версии, manifest id, generated-карты,
  release-файлы и формат хранимых данных, если это прямо не разрешено заданием.
- Не делай commit, push, reset, checkout или очистку рабочей директории.
- Не удаляй пользовательские файлы. Не запускай установщики.
- Если условие невозможно выполнить безопасно, остановись и запиши блокер в
  отчёт вместо самовольного изменения архитектуры.

## Обязательная проверка

После любых изменений:

1. Запусти указанные в задании целевые тесты.
2. Запусти полный `node tests/run-all.js`.
3. Просмотри `git diff --check` и `git diff --stat`.
4. Просмотри собственный diff на случай лишних файлов, отладочного кода,
   случайного форматирования и потери исходных изменений.
5. Не исправляй нерелевантные дефекты, найденные по пути; перечисли их отдельно.

## Отчёт, который обязан остаться в репозитории

Для задания `NNN-name.md` создай `.agents/reports/NNN-name.md` по шаблону
`.agents/reports/TEMPLATE.md`. Отчёт является частью результата и должен
содержать факты, а не только фразу «готово».

Обязательно укажи:

- статус: `completed`, `partial` или `blocked`;
- исходное состояние и baseline тестов;
- список изменённых файлов и смысл каждой правки;
- принятые решения и отклонения от задания;
- команды проверок, exit code и точные итоги тестов;
- что не проверено и какие риски остались;
- краткую инструкцию ручной проверки UI;
- `git diff --stat` после работы.

Не редактируй файл задания и не создавай ревью: `.agents/reviews/` принадлежит
Codex. Не сохраняй единственную копию отчёта только в Antigravity Brain — отчёт
в `.agents/reports/` обязателен.

## Критерий завершения

Работа Gemini считается переданной, но не принятой, когда код и отчёт готовы и
полный набор тестов пройден. Работа считается принятой только после отдельного
ревью Codex в `.agents/reviews/`.
