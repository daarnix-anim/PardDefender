# Задача 005: UI отчёта о дубликатах

Статус: ready

Зависит от: задача 004.

## Цель

Добавить безопасный read-only интерфейс поиска точных дубликатов в AE-панель.
Никаких relink/delete/merge на этом этапе.

## UX

- Вкладка `ДУБЛИКАТЫ` появляется после первого scan, если есть группы или
  ошибки, и имеет badge с количеством групп.
- В настройках/вкладке есть кнопка `НАЙТИ ДУБЛИКАТЫ`; во время работы — progress
  по файлам и байтам и кнопка `ОТМЕНИТЬ`.
- Каждый group показывает: тип (file/sequence), размер одной копии, потенциально
  освобождаемое место, все пути, число project references, ownership и
  рекомендуемый canonical с понятной причиной.
- Можно вручную выбрать canonical только среди проверенных членов группы.
- У missing/unstable/unreadable элементов виден code и действие «показать», если
  путь доступен. Они не считаются безопасными группами.
- После изменения audit report старый результат помечается устаревшим и требует
  нового scan; он не используется для будущей операции.
- Тексты ясно говорят: это точные дубликаты; файлы пока не изменены и не удалены.

Сохранять только пользовательский canonical override в
`.parddefender/settings.json` по `contentId`; исчезнувшие group id очищать при
новом scan. Не запускать тяжёлый scan автоматически при каждом timer tick.

## Интеграция

Подключить `duplicate-index.js` до `main.js`, расширить render-signature подход,
не сбрасывать scroll неизменившихся групп. Scan не должен блокировать обычный
audit/copy queue, но одновременно допускается только один duplicate scan.

## Тесты

Расширить panel harness: наличие обработчиков, progress/cancel, группы и badge,
canonical override, stale state после изменения проекта/audit, ошибка без
потери последнего результата, отсутствие лишних `innerHTML` writes, отсутствие
любых relink/recycle вызовов из read-only UI.

Обновить README кратким описанием. Не менять версию. Запустить полный набор и
создать `.agents/reports/005-duplicate-report-ui.md`.
