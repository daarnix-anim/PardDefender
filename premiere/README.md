# PardDefender для Adobe Premiere Pro (UXP)

Отдельный плагин нового поколения для Adobe Premiere Pro на базе официальной архитектуры
Adobe UXP (Unified Extensibility Platform), manifestVersion 5.

## Требования

- **Adobe Premiere Pro:** версия 25.6 или выше.
- **Архитектура:** UXP manifestVersion 5.
- **Запрещённые технологии:** QE DOM, ExtendScript, CEP, `evalScript`, прямое редактирование закрытых `.prproj` файлов не используются.

## Разрешения (Permissions)

В `manifest.json` запрошено разрешение:
```json
"requiredPermissions": {
  "localFileSystem": "fullAccess",
  "clipboard": "readAndWrite"
}
```

### Почему `fullAccess`?
В отличие от веб-приложений, пользовательские видеопроекты Premiere Pro и исходные медиафайлы
могут находиться в произвольных директориях локальных накопителей и сетевых хранилищ.
UXP требует `fullAccess` для чтения и организации медиа рядом с открытым файлом проекта.

**Гарантия безопасности:** PardDefender строго ограничивает любые операции рамками
разрешённой рабочей папки проекта (`workspaceRoot`), определяемой по расположению
активного `.prproj`. Никакие файлы за пределами рабочей папки проекта не модифицируются.

## Установка и запуск в режиме разработки (Dev Load)

### Способ 1: Через Adobe UXP Developer Tool (UDT) (Рекомендуется)
1. Установите и запустите официальный **Adobe UXP Developer Tool** из Creative Cloud Desktop.
2. Нажмите **Add Plugin** и выберите файл `premiere/com.pard.defender.uxp/manifest.json`.
3. Запустите Adobe Premiere Pro (версия 25.6+).
4. В UDT в строке плагина выберите **Actions -> Load**.
5. В Premiere Pro откройте панель через меню: **Окно (Window) -> Подключаемые модули UXP (UXP Plugins) -> PardDefender**.

### Способ 2: Запуск установочного скрипта
Запустите `INSTALL_DEV_WINDOWS.bat`. Скрипт скопирует файлы и автоматически настроит `Debug Database.txt` в настройках Premiere Pro (`dvauxphost.UseDebugUXPDir` и `dvauxphost.DebugUXPDir`), после чего плагин появится в **Окно -> Подключаемые модули UXP -> PardDefender**.

### Способ 3: Установка готового пакета .CCX
Дважды кликните по файлу `release/PardDefender-2.3.2.ccx` (через Adobe Creative Cloud Desktop). При отсутствии приложения Creative Cloud воспользуйтесь Способом 1 или Способом 2.

## Возможности плагина

### Ошибки файлов UXP и читаемый журнал (044)

- Отсутствующее назначение теперь позволяет создать защищённую копию. Числовые
  ошибки UXP и ошибки без поля code приводятся к одинаковым кодам на границе I/O.
- Папки создаются по уровням после проверки существования. Готовая папка проекта
  и служебная .parddefender не создаются заново.
- Сбой показывает код, операцию и точный путь. Ошибка доступа сохраняет отказ.
- Строки журнала имеют отдельную высоту и переносы. Повторяющиеся диагностики
  не дублируются; на экране остаются последние 300 записей. «Очистить экран журнала»
  очищает только видимый список, файл session.log сохраняется.

### Исправление защиты и панели (043)

- Копирование использует документированный UXP `lstat` вместо отсутствующего
  `stat`. Снимок для AE и реестр проектов записываются асинхронно: UXP не
  предоставляет `mkdirSync` и `renameSync`.
- Сходство имени с файлом AE — только кандидат на проверку. Если байты отличаются
  или кандидат отсутствует, исходный ролик защищается отдельно в папке проекта.
  Существующий файл AE не заменяется.
- Результат защиты и ошибки остаются видны после повторного сканирования.
  Сохранён один общий сканер проекта и одна кнопка паузы в шапке.
- Клик по строке открывает существующий ProjectItem в мониторе «Источник»,
  а не импортирует файл повторно. Путь по папкам Premiere указан в строке.
  Выделение в панели «Проект» официальным UXP API пока не предоставляется.
- Перед удалением внешних исходников нужно подтвердить успешную перелинковку,
  сохранение проекта и внутренний путь каждого файла. Проверки на макетах API
  не заменяют прогон внутри Premiere.

### Уточнённые правила защиты (исправление 042)

- Корень рабочей зоны — родитель `04_edit`; `.prproj` и `.aep` используют общую
  `.parddefender`. Обычное видео копируется в `01_assets/_SHARED/VIDEO`, изображения —
  в `01_assets`, нумерованные последовательности кадров — в `05_shot_production`.
- Музыка, голос и эффекты относятся к зоне ответственности Premiere:
  `03_audio/music`, `03_audio/voice`, `03_audio/sfx`. Папка `sound` больше не
  переопределяет эту структуру. Защищённые AE визуальные файлы остаются на пути AE.
- Тип звука определяется по папке Premiere, имени и пути; в карточке есть ручной
  выбор «Голос / диктор», «Музыка», «Звуки / SFX». Неопределённый звук сначала
  защищается непосредственно в `03_audio`, без выдуманного типа. После выбора типа
  повторная защита копирует его в соответствующую подпапку и перелинковывает.
- Чтение классификации панели **Essential Sound** пока не реализовано:
  проверенного контракта получения её типа через UXP в этом проекте нет.
  Нельзя считать имя `Untitled.mp3` признаком музыки.
- Метка **AE защита** показывается и на уже перелинкованном файле при наличии
  снимка проекта After Effects либо записи с явным авторством AE. Общий legacy
  `assets.tsv` без авторства сам по себе не доказывает защиту AE.
- Копирование идёт блоками по 256 КиБ; исходник и копия проверяются SHA-256.
  Зависшая файловая операция завершается ошибкой через 30 секунд без ложного успеха.
  Оригиналы и отличающиеся существующие файлы назначения не удаляются.
- AE при следующем сканировании следует аудиопути из снимка Premiere даже тогда,
  когда сам уже успел сохранить старую копию внутри проекта. Закрытые проекты
  не редактируются: открыть AE, обновить сканирование и выполнить защиту.
- Сохранено прежнее ограничение панели: защита применяется к используемым
  на таймлайне медиа. Перемещение в `unused` — отдельная операция.

- **Интерфейс панели:** три вкладки («ЗАЩИТА», «ДУБЛИКАТЫ», «ЖУРНАЛ»).
- **Официальный UXP-адаптер (`adapter.js`):**
  - Определение активного проекта, GUID, пути и рабочей папки;
  - Корректная обработка несохранённых проектов;
  - Рекурсивный сбор медиафайлов по структуре папок (bins);
  - Извлечение путей исходников (`ClipProjectItem.getMediaFilePath()`);
  - Распознавание proxy (`hasProxy()`, `getProxyPath()`);
  - Классификация элементов: клипы, секвенции, multicam, merged, offline, generated (титры, подложки, настроечные слои);
  - Интеграция с реестром проектов `.parddefender/projects.json` с сохранением стабильного GUID при «Сохранить как».
- **Защита медиафайлов (`copy-engine.js`):**
  - Кнопка «ЗАЩИТИТЬ СЕЙЧАС» копирует внешние медиафайлы в `01_assets/_SHARED/VIDEO` рабочей папки проекта;
  - Асинхронное поблочное копирование с инкрементальным SHA-256 (NIST векторы);
  - Временные файлы `.pdpart`, валидация размера и контрольной суммы до атомарного rename;
  - Журналирование до записи (`pending.tsv`) и аварийное восстановление;
  - Фиксация provenance в `.parddefender/assets.tsv`;
  - Перелинковка через `ClipProjectItem.changeMediaFilePath(newPath, false)` с проверкой `canChangeMediaPath()` и post-relink verification.
- **Поиск дубликатов и консолидация (`duplicates.js`):**
  - Поиск 100% побайтовых копий с группировкой по SHA-256;
  - Рекомендация каноникала и возможность ручного переопределения;
  - Кнопка «ОБЪЕДИНИТЬ В ОДИН ФАЙЛ» с двухкликовым подтверждением (6 секунд окно защиты);
  - Re-verification хэша каноникала (`REHASH_MISMATCH` блокирует операцию);
  - Копирование внешнего каноникала в проект с фиксацией в `assets.tsv` до перелинковки;
  - Строгая гарантия безопасности: исходные файлы на диске НЕ удаляются, проектные элементы НЕ удаляются.

## Отличия от After Effects версии

1. **Нет сканирования забытых слоёв:** в Premiere Pro нет концепции скрытых/забытых слоёв («выключено и забыто»), так как структура таймлайна и клипов в bin отличается от композиций After Effects.
2. **Нет композиционной раскладки:** папки проекта (bins) в Premiere Pro отражают монтажную структуру пользователя и не форматируются по иерархии рендерных композиций.
3. **Асинхронная UXP-модель:** все вызовы к хосту выполняются через официальный объектный DOM UXP, без вызовов синхронного ExtendScript.
